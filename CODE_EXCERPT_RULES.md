# Code excerpt rules

Use these rules for every Ballerina code excerpt in EIP pattern pages.

- Include only the relevant code for the implementation concept.
- Do not include complete files by default.
- Include imports or type definitions only when they are needed to understand the excerpt.
- When supporting definitions are useful for the excerpt but are not necessary to explain the pattern, keep them in the source and hide them with `// docs-fold-start: Supporting definitions` and `// docs-fold-end` instead of removing them.
- Avoid repeating imports across tab sections.
- Use comments only when they explain EIP-relevant behavior.
- Keep prose product-focused. Use "The following code..." instead of "The following Ballerina code...".
